# 稳定版候选质量计划

本文记录从 0.1.0 实验原型走向稳定版候选所需的证据。它不是发布日期承诺；所有项目全部通过后仍需项目所有者明确确认，才能决定是否发布正式版。

## 当前架构审计

| 模块 | 当前职责 | 已有保护 | 主要缺口 |
| --- | --- | --- | --- |
| `main.lua` | KOReader 菜单、网络任务和阅读入口 | 操作反馈、删除确认、独立书籍状态、可取消子进程、可信用户错误令牌和未预期异常固定提示 | 需要实机验证取消、重复点击、Wi-Fi 切换、错误提示布局和强制退出 |
| `http.lua` | 官方 HTTPS GET | 官方域名白名单、KOReader CA 链验证、SAN 主机名验证、禁用重定向、1 MB、20 秒、长度检查、原始传输错误固定分类 | DNS 解析不受总超时完全控制；设备时间、网络切换和 TLS 真机差异仍待验证 |
| `parser.lua` | 书籍、目录、章节和 XHTML | 固定 JSON 解码错误、ID 校验、短预览/锁定/未知 PUA 安全拒绝、首批去正文结构夹具 | 兼容矩阵自动门禁已建立，但 30 本/90 场景真实证据尚未采集 |
| `library.lua` | 多书书架、迁移和进度 | 版本化迁移、去重、边界修正、降级字段 | 需验证设置写入中断、升级/降级和多次强制退出 |
| `persistence.lua` | 插件设置与上一版备份 | 凭证字段拒绝、序列化/写入/fsync/关闭检查、重读复验、原子替换、固定错误和内存回滚 | 目录 fsync 为替换后 best-effort；断电、只读分区和空间不足仍需真机验证 |
| `storage.lua` | 章节缓存 | 临时文件 fsync、关闭后重读复验、原子改名、每书 12 章、损坏缓存拒绝、严格删除白名单、文件系统异常固定分类且不字符串化异常对象 | 目录 fsync 为替换后 best-effort；需实机验证断电、只读磁盘、空间不足和部分清理失败的用户提示 |
| `import.lua` | JSON 文件导入 | 256 KB、500 本、字段白名单、凭证拒绝、固定解码错误、全量验证后确认 | Kindle 文件选择与导入已单机实测；仍需用测试账号验证浏览器导出 |
| `export.lua` | 本地书架 JSON 导出 | 最小字段投影、导入器复验、原子替换、固定编码错误 | 已在一台 PW3 实测正常导出；编码失败与磁盘失败仅有合成证据 |
| `ephemeral_session.lua` | 一次性扫码生命周期核心 | 单实例运行代号、取消/过期/总超时、固定字段/大小的复制凭证袋、退出后清理、固定错误、严格最小书架验证 | 尚未接入 UI/网络；真实凭证字段映射、二维码、退出语义和强制进程退出仍待审计 |
| `ephemeral_task.lua` | 一次性敏感子任务 IPC 门禁 | 匿名管道简单字符串模式、固定帧/提示/错误、异常封装、256 KB 双向检查 | 尚无真实 HTTP；任务自身日志、Cookie jar、取消后的远端状态仍待审计 |
| `ephemeral_http.lua` | 未启用的敏感 HTTPS 子任务客户端 | 复用 CA/SAN、固定官方主机与操作白名单、请求/响应/头上限、代理/重定向拒绝、固定错误、无文件/日志 | 尚无真实端点、Cookie 语义、轮询/退出编排或真机证据；成功正文和允许响应头仍是敏感内存 |
| `ephemeral_result.lua` / `ephemeral_import_task.lua` | 最小书架匿名管道门禁 | 现有导入白名单、凭证拒绝、标准化编码、编码后与父进程双重复验、固定错误 | 尚无真实响应解析器和完整网络/退出任务；无法识别被错误映射进普通标题字段的秘密值 |
| `qrdisplay.lua` | 原生内存二维码显示适配 | 2048 字节硬上限、控制字符/时限验证、单实例、关闭清理、固定错误 | 尚未接入扫码流程；需 PW3 验证扫码可读性、关闭回收及前后文件变化 |
| `tools/export-bookshelf.js` | 浏览器最小书架导出 | 精确官网页面/路径白名单、不读取 Cookie、2 MB 流式响应上限、固定错误、只输出 256 KB 白名单 JSON | 仍是原型；需要测试账号验证官方动态接口、字段映射和下载流程 |

## 优先级

### P0：合并任何功能前必须完成

1. 在备份现有设置后，用 Kindle 验证 0.1.0 单书数据迁移、多书切换、离线缓存、移除和清缓存。
2. 固定源码与官方 Kindle 包已确认默认 LuaSec 不验证证书、KOReader 包内含 CA 集；公开 HTTPS 已改为显式证书链与 SAN 校验并通过合成失败测试。仍须验证断网、慢响应、TLS/时间错误、响应过大、重定向及 PW3 真实握手不会卡死 KOReader。
3. 损坏缓存、设置写入失败、磁盘写满和自动淘汰失败已有可复现测试与安全提示；设置错误 canary 已覆盖序列化、创建、同步、关闭、改名和主界面回滚。只读磁盘和空间不足仍待实机确认。
4. 在实机验证基于 KOReader 2026.03 `Trapper:dismissableRunInSubprocess()` 的可取消网络任务：点按取消、重复点击、Wi-Fi 切换和强制退出。
5. 任何堆叠 PR 只有在可靠的“遇错即停”CI 下重新通过，才算有效证据。

### P1：默认本地书架达到日常可用

1. 建立 30 本书、至少 90 个章节场景的兼容矩阵，规则见 `compatibility-matrix.md`。
2. 已为当前已知的书籍页、卷目录、平铺目录、ID 目录、公开章节和安全拒绝状态建立首批去正文最小夹具；真实矩阵遇到的新结构仍须先脱敏再补充。
3. 缓存损坏检测、目录更新时间和更清楚的离线状态已实现并通过自动测试；界面显示仍待实机确认。
4. 完成 JSON 浏览器导出测试账号验证与新手文档。
5. 搜索保持暂缓：2026-08-16 官方搜索接口直连返回空正文，公开搜索页触发滑块验证。不得绕过验证码，也不得用第三方搜索替代；只有找到可在 Kindle 上合法稳定使用的官方路径后再实现。

### P2：可选账号导入

1. 独立威胁模型已列出 Cookie 生命周期、Lua 内存限制、日志脱敏、取消/超时、退出失败、强制退出和 No-Go 条件；端点无关状态机、内存 QR、匿名管道与敏感 HTTPS 门禁已有合成测试，当前官方接口、真机 QR 行为、Cookie 语义、任务编排和远端退出语义仍须重新验证。
2. 仅用无敏感内容的测试账号验证一次性二维码。
3. 自动检查设置、缓存、日志和崩溃输出中不存在 Cookie、session、CSRF、Token 或请求头。
4. 扫码成功、失败、取消、过期和退出失败均不得影响本地书架。
5. 未通过安全审计前始终标记为实验性，且不实现长期登录或后台同步。

## 发布候选门禁

- 30 本/90 场景矩阵完成；公开且允许读取的样本正确解析率至少 95%。
- 所有未知 PUA、登录墙、付费锁定、章节 ID 不一致和畸形响应安全拒绝。
- Lua 5.1、浏览器工具和导入安全测试全部通过，CI 不会掩盖中间失败。
- 至少完成一次升级、重启、降级和卸载回退实机演练，并记录设置与缓存变化。
- 固定白名单候选包及 5 分钟安装文档通过自动结构检查；仍须由未接触项目的新手按步骤计时验证，确认能从已安装 KOReader 到开始阅读。
- 生成候选包、测试证据和评估报告；不自动合并、打 `1.0` 标签、创建正式 Release 或宣传。

## 当前证据状态

- 0.1.0 已在 PW3 5.16.2.1.1 + KOReader 2026.03 验证单书、88 章目录和公开正文阅读。
- 开发栈已在同一台 PW3 验证 0.1.0 单书迁移、多书共存与切换、旧章节缓存和 KOReader sidecar 保留，以及测试书移除后通过 JSON 恢复；降级和强制退出仍未实机覆盖。
- 飞行模式下本地书架、两本书切换及两本已缓存章节均正常；测试书恢复约 75% 本机位置，原书也保留自身位置。清理测试书缓存精确删除 1 个 XHTML，保留 `.sdr`、28/87 章目录和另一本文档缓存；离线缺缓存时请求联网且取消安全，联网重建后仍恢复约 75%，全程没有乱码、报错或闪退。
- 网络边界、可取消子进程、损坏缓存和部分清理失败已有自动测试与 CI。针对 KOReader 2026.03 固定源码及官方 Kindle 包的审计发现 LuaSec 1.3.2 默认 `verify = "none"` 且不校验主机名；公开 HTTPS 现已显式使用包内 CA 集验证链，并对证书 SAN 做精确/单标签通配符匹配，缺失、畸形或不匹配均关闭连接。详见 [`TLS_SECURITY_AUDIT.md`](TLS_SECURITY_AUDIT.md)；尚未在 PW3 执行真实握手、错误证书或异常系统时间矩阵。
- 公开网络错误 canary 测试证明 socket 原始字符串、异常对象、非字符串子进程错误和主界面未捕获对象不会进入用户提示，也不会触发自定义 `__tostring`；取消、超时、TLS、HTTP 状态和本地数据安全说明仍保留。该证据不覆盖 KOReader 崩溃收集器、真实系统错误文案或真机弹窗布局。
- 设置写入 canary 测试证明序列化器返回异常对象、临时文件创建抛错、fsync/关闭失败和原子改名抛错都不会回显原始值或调用 `__tostring`；临时文件被清理、正式设置保持原样，主界面内存书架恢复到上一版。目录 fsync 仍是替换后的 best-effort，本证据不等于断电级持久性验收。
- 缓存文件系统 canary 测试证明属性读取、目录打开/迭代、临时文件创建/写入/fsync/关闭、替换前重读复验、原子改名、章节读取、自动淘汰和手动部分清理不会回显异常对象、底层路径或调用 `__tostring`；失败只显示固定阶段或程序统计数量，未完成 `.tmp` 会清理，删除仍仅匹配数字命名的插件缓存。文件正文会在替换前同步并复验，目录同步为替换后 best-effort；本证据不等于断电、只读或满盘实机验收。
- 严格 JSON 已在 PW3 完成文件选择、确认、导入、28 章目录加载、阅读位置一次性恢复和 2 本书本地导出；导出文件通过插件严格导入器复验且无凭证、正文、缓存或临时残留，浏览器导出仍未使用测试账号验证。
- JSON 解析异常、`decode()` 错误正文和导出 `encode()` 异常现在都被固定分类取代，编解码层不再对异常对象调用 `tostring()`；合成对象的 `__tostring` 与错误正文包含凭证 canary 时，书架导入、导出和官方响应提示均不含 canary。搜索非零状态只回显 `tonumber()` 验证后的数字码，原始字符串被丢弃。该证据不替代真机误选畸形文件或导出失败后的界面布局检查。
- 浏览器导出器合成测试覆盖完整下载、跨域和近似路径拒绝、网络/读取/HTTP/JSON 固定错误、声明与实际响应超限，以及官方响应额外 Cookie、Token、sessionid、CSRF 和手机号字段丢弃。测试同时锁定源码不读取 `document.cookie`/Web Storage、不调用控制台、不读取服务端 `message`、不把原始异常字符串化；仍未用测试账号确认当前官网字段与浏览器下载行为。
- 草稿 PR #19 已记录文件选择确认框修复：首次约 60% 导入位置应用后，本机约 75% 位置在重新打开时优先恢复；最新 CI 通过。
- 兼容证据工具已能强制检查 30 本/90 场景、五档书长、12/18 完结状态、每本前中末、单一候选提交、95% 公开解析率及六类安全拒绝覆盖；真实矩阵仍未开始，不能据此声称兼容率达标。
- 书籍页本地状态已区分目录章数、缓存文件数、目录刷新时间、旧数据未知时间和设备时间异常，并明确离线边界；自动测试通过，尚未写入 Kindle 验证布局与操作手感。
- 首批解析夹具只含合成文字和虚构 ID，覆盖 3 种书籍状态、7 种目录状态和 10 种章节状态；重复/部分非法目录、非法数字实体和通过实体出现的未知 PUA 均会在缓存前安全拒绝。它不能替代真实 30 本矩阵。
- 自动缓存淘汰现在会统计并报告目录不可读与旧文件删除失败，且不因异常时间戳误删刚写入的当前章节；新章节仍可阅读，用户会获得安全状态和手动清理建议。真实只读磁盘与空间不足提示尚未在 PW3 验证。
- 候选测试包构建只纳入运行 Lua、许可证、README、变更记录、安装指南及七份安全/格式/质量文档，固定单层插件目录、1 MB 上限、提交号和 SHA-256；默认拒绝脏工作区，CI 会解包复验精确清单、提交身份和 Lua 语法。安装指南尚未经过陌生新手 5 分钟计时测试，不能据此宣布门禁完成。
- 扫码威胁模型已定义敏感资产、信任边界、状态机、退出和强制退出风险、合成/测试账号矩阵及 No-Go 条件。`state_table()` canary 测试证明瞬时根状态不进入设置，书架导入丢弃额外凭证字段，`Persistence.write()`还会在创建主文件或 `.old` 前拒绝嵌套凭证字段；这些只证明设计前置门禁，不代表真实扫码已实现或安全审计完成。
- 端点无关的一次性会话核心已用合成 canary 覆盖成功、重复开始、无效/超长/控制字符 QR、授权凭证未知字段/控制字符/超限/缺少主凭证、调用方表修改隔离、取消、QR 过期、总超时、固定失败、退出失败、迟到旧结果、恶意书架数据、提交失败重试和强制本地清理。授权后只持有 `cookie`、`authorization`、`csrf_token`、`logout_ticket` 的受限副本；准备确认前会先尝试退出，退出回调成功、失败或取消返回后都清空交给回调的表，再删除模块引用。该证据不覆盖回调另行复制的字符串、真实字段映射、进程被杀或服务端会话失效。
- KOReader v2026.03 的 `QRMessage`/`QRWidget`/`ffi/qrencode.lua` 固定源码链表明二维码矩阵和图像可在内存生成；适配层会在上游 2953 字节静默截断前以 2048 字节硬上限拒绝，验证单实例、控制字符、显示失败、关闭失败重试和关闭后 canary 不可达。仍需 PW3 验证实际扫码可读性、触摸/按键/超时关闭、内存释放及用户分区前后无新增二维码文件。
- KOReader v2026.03 的 `Trapper` 与 `ffi/util.lua` 固定源码表明子进程返回值走 POSIX 匿名管道而非临时文件；默认复杂序列化、畸形解码和未捕获异常存在日志风险。独立门禁强制简单字符串模式、内部 `pcall`、固定帧和 256 KB 双向限制，合成 canary 覆盖异常、取消、错误类型、空值、超限、畸形帧和 Trapper 异常。它不证明未来 HTTP/Cookie 任务本身不写日志或文件。
- 未启用的 `ephemeral_http.lua` 复用同一 `verified_tls.lua`，只接受固定官方主机上的代码内操作名、精确路径和 GET/POST 方法；动态 URL/查询串、未知参数/头、代理、重定向、超限正文/响应和原始异常都会被拒绝。合成 canary 证明错误不回显凭证、未列出的响应头不暴露、超时总会复位且源码不调用日志/文件/进程输出。允许返回的成功正文与 `Set-Cookie` 仍是子进程敏感内存；真实端点和 Cookie 合并/过期语义仍未实现。
- `ephemeral_result.lua` 会在子进程内复用严格 JSON 导入器，删除非必要顶层数据，把内部进度重新投影为最小字段，编码后立即解码复验；`ephemeral_import_task.lua` 只把该字符串交给简单匿名管道，父进程再次验证后才返回标准化书籍。canary 测试覆盖 Cookie 字段、生产者/编解码异常、凭证复验和管道篡改，主入口仍未导入该模块。它不能替未来真实响应解析器证明某个普通标题值不是被误映射的秘密，也不实现退出。
- 30 本/90 章节兼容矩阵、一次性扫码导入安全审计、新手 5 分钟安装测试和发布候选评估报告均未完成。
- 稳定版候选条件仍未满足。
