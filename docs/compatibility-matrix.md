# 兼容性测试矩阵方法

目标是测试代表性差异，不是挑选容易成功的样本，也不是批量下载小说。

## 取样配额

共 30 本书，按测试时目录长度分层：

- 少于 50 章：5 本
- 50–200 章：5 本
- 201–500 章：8 本
- 501–1000 章：7 本
- 超过 1000 章：5 本

其中至少 12 本已完结、18 本连载中；兼顾男频、女频、出版或版权受限提示、新书和较早作品。只选番茄官网公开可定位的书籍，不使用第三方书源。

每本书最多主动读取 3 个章节场景：目录前部、中部和当前末尾，共至少 90 个场景。不下载整本，不保存或提交完整正文。最终完成门禁要求每本纳入统计的书恰好各有一个互不重复的前、中、末场景；少于 3 章的书不能用于这组固定矩阵。

## 每个场景记录

- 测试日期、设备/桌面环境和插件提交号
- 书籍 ID、目录章数、连载状态和分类
- 章节位置（前/中/末）与章节 ID
- 响应或安全验证类型：公开正文、短预览、登录墙、锁定、限流、畸形响应或 ID 不一致
- 解析结果：成功、安全拒绝、错误接受或解析失败
- 可见字符数、声称字数、已知 PUA 数和未知 PUA 数
- 是否保存缓存、是否出现乱码、错误提示是否可操作
- 页面结构指纹或字段集合；不记录 Cookie、Token、请求头或完整正文

仓库中的 `tools/compatibility-evidence.js` 只接受逐行 JSON 记录，并采用固定字段白名单。记录不含书名、作者、章节标题、正文、原始响应或任何请求头；`structure_sha256` 仅用于区分页面结构，不可由完整正文生成。运行：

```sh
node tools/compatibility-evidence.js path/to/records.jsonl
```

工具会拒绝额外字段、错误 ID、异常计数、重复章节场景和非 SHA-256 指纹，并汇总公开正文正确率与非公开或异常响应的安全拒绝率。真实证据文件在完成隐私复核前不得提交仓库。

采集中可继续使用上述命令查看部分进度。准备评估完整矩阵时运行：

```sh
node tools/compatibility-evidence.js --require-complete path/to/records.jsonl
```

完整门禁会以非零状态拒绝以下任一缺口：少于 30 本或 90 个场景；五档目录长度未达到 5/5/8/7/5；少于 12 本完结或 18 本连载；任一本缺少互不重复的前、中、末场景；样本混用不同插件提交；缺少男频、女频及出版或版权受限样本；公开正文正确解析率低于 95%；短预览、登录墙、锁定章节、畸形响应、章节 ID 不一致或未知 PUA 没有至少一个安全拒绝场景；任何需拒绝场景写入缓存、显示乱码或缺少可操作错误提示。

工具不能从匿名书籍 ID 可靠判断“新书/较早作品”，也不能证明结构哈希的生成来源，因此这两项仍必须人工复核。限流只在自然遇到时记录并停止本轮，不得为了填满类型主动触发平台风控。

## 统计口径

“正确”同时包括：公开完整正文被正确解析，以及短预览、登录墙、付费锁定、未知 PUA、章节 ID 不一致和畸形响应被安全拒绝。安全拒绝必须不保存缓存、不显示乱码，并给出可操作的错误提示。

公开解析率的分母只包含官网在测试时明确返回完整公开正文的场景。其余响应和未知 PUA 场景另行统计安全拒绝率，不能从失败样本中删除来美化结果。

## 请求纪律

- 串行、低频执行，章节请求之间至少间隔 2 秒。
- 遇到 429、验证码或官方风控立即停止本轮，不重试绕过。
- 只记录最小统计与不可逆哈希，不提交正文夹具。
- 每轮开始前重新确认官方页面条款和接口结构；网页变化后旧结果标记为历史证据。
