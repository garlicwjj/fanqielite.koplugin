# 书架 JSON 文件格式（版本 1）

文件必须命名为 `fanqielite-bookshelf.json`，使用 UTF-8 编码，且不超过 256 KB。插件一次最多接受 500 本书。

```json
{
  "format": "fanqielite-bookshelf",
  "version": 1,
  "exported_at": "2026-08-16T12:00:00Z",
  "books": [
    {
      "id": "7633875868615461950",
      "title": "示例书名",
      "author": "示例作者",
      "cover_url": "https://example.invalid/cover.jpg",
      "current_chapter_id": "10000000002",
      "current_chapter_title": "第二章",
      "reading_position": 0.5
    }
  ]
}
```

`id` 与 `current_chapter_id` 必须是 10 到 64 位的数字字符串，不能写成 JSON 数字，否则 19 位 ID 可能丢失精度。64 位上限为未来格式保留余量，同时避免异常输入膨胀设置和缓存路径。`reading_position` 可省略；存在时必须是 0 到 1 的数字。除 `id` 和 `title` 外，其余书籍字段均可省略。

导入的 `reading_position` 只会在对应章节首次打开且 KOReader 尚无该 XHTML 的本机 sidecar 时应用一次。已有本地目录/阅读记录的书不会被导入进度覆盖；即使书籍曾从书架移除，只要缓存旁仍有 KOReader sidecar，本机位置仍优先。

插件使用严格字段白名单。文件中不得包含 Cookie、Token、session、CSRF、手机号、密码、授权头或其他账号凭证；出现凭证字段或未知字段时，整个文件都会被拒绝，现有书架不会改变。错误提示不会重复显示原始字段名或字段内容。

如果文件不是合法 JSON，插件只显示固定的“书架 JSON 解析失败”分类，不会回显解析器原始异常或文件内容附近文本；现有本地书架不会改变。

导入只建立本地书架记录，不会联网，也不会上传数据。新导入的书籍首次打开时，用户需要主动联网获取官方目录。封面地址目前只保存、不下载。

## 从 Kindle 导出本地书架

在插件的“设置与数据 → 导出本地书架”中确认后，会把同格式文件写到 Kindle 用户盘根目录。写入采用同目录临时文件、存储同步、导入白名单复验和原子替换；任一步失败都会报告失败，不改变插件书架、章节缓存或设置。JSON 编码失败只显示固定分类，不会回显编码器异常或本地书架内容。

本地导出只包含书名、作者、封面地址和当前章节。插件尚未记录 KOReader 文档中的章节内百分比，因此不会伪造 `reading_position`；只有尚未获取本地目录、且进度来自已验证导入文件时，才保留该文件中的合法百分比。该位置在首次安全应用或因本机 sidecar 优先而丢弃后，不会继续导出。该文件连接电脑后可被读取，属于个人阅读数据，请自行妥善保管。

## 从浏览器导出

仓库中的 [`tools/export-bookshelf.js`](https://github.com/garlicwjj/fanqielite.koplugin/blob/main/tools/export-bookshelf.js) 只能在 `https://fanqienovel.com/bookshelf` 页面执行。它复用浏览器当前已经登录的会话，只向代码中固定的同源精确只读路径发起请求；从页面性能记录发现的跨域、近似路径、带用户信息或片段地址都会在请求前拒绝。脚本不会读取、显示或写入浏览器 Cookie，也不读取 Web Storage。

每个响应按 UTF-8 流式读取并限制为 2 MB，生成文件仍限制为 256 KB。脚本只生成本页格式白名单中的书籍数据，不包含 Cookie、Token、手机号或请求头；网络异常、HTTP 失败、服务端消息、畸形 JSON 和读取异常只显示固定分类，不会把原始正文或异常带入弹窗或控制台。书架中已知的非小说类型会排除；其余受支持条目必须全部提供合法 ID，详情响应必须与这些 ID 一一对应并包含非空安全书名。任何缺失、重复、额外详情或未知结构都会在下载前整体停止，不会用占位书名生成残缺备份。已发现的阅读进度响应也会限制数量并验证每项对象、书籍 ID、导出书籍的唯一记录及章节 ID；章节标题兼容当前公开模型字段，书架外的合法历史记录不会导出。三个公开进度比例字段尚未证明章节内语义和量纲，因此当前不会猜测生成 `reading_position`。专用测试账号已经完成两本未读书的一次真实先导导出，但字段和规模覆盖仍不足；当前继续作为开发验证工具，不建议普通用户使用。

### 安全导出步骤（开发验证）

当前步骤只在桌面 Chrome 和专用测试账号的两本未读书上完成过一次先导验证。作者、已读进度、分组、多页和大书架仍未验证；在这些证据补齐前，不要把它当作成熟的账号同步功能，也不建议使用含敏感书架数据的主要账号。

1. 在桌面 Chrome 登录番茄小说官网，精确打开 `https://fanqienovel.com/bookshelf`，确认官方书架已经显示完成。不要停留在移动端下载 App 提示页。
2. 从本候选包的 `BUILD-INFO.txt` 读取完整提交号，在项目 GitHub 页面切换到同一提交，再打开 `tools/export-bookshelf.js`。只使用 `garlicwjj/fanqielite.koplugin` 仓库中的完整文件；不要执行评论区、网盘或陌生站点提供的改写版本。
3. 打开 Chrome 开发者工具，进入“源代码（Sources）→ 代码段（Snippets）”，新建代码段，粘贴完整脚本后运行。浏览器若显示防诈骗粘贴警告，在确认仓库和提交前应停止；不要为了跳过警告执行来源不明的短命令。
4. 成功时页面会提示“已导出 N 本书”，并下载固定文件 `fanqielite-bookshelf.json`。不要粘贴 Cookie、Token、手机号或请求头，也不要修改脚本中的官方路径来绕过失败。
5. 若提示没有找到官方书架请求，先刷新官方书架页，等书架重新显示后再运行一次；仍失败就停止使用当前工具，不要反复登录或尝试抓取其他接口。页面没有产生阅读进度请求时，脚本会导出不含进度的最小书架；如果已经请求进度但官网返回登录失效、其他失败状态或未知结构，脚本会停止且不下载残缺文件。
6. 用 USB 把这个固定文件名复制到 Kindle 用户盘。安全弹出后，在 Fanqie Lite 打开“设置与数据” → “从文件导入书架”，选择文件并核对确认框中的书籍数量，再确认导入。
7. 导入采用合并，不会覆盖已有本地书架：新 ID 会新增，同 ID 只更新经过白名单验证的基础资料，并保留已有目录与本机阅读位置。确认书架正常后，可删除电脑和 Kindle 用户盘上的中转 JSON；它不含登录凭证，但包含个人书架与可能的阅读位置，应按私有阅读数据保管。

这套步骤没有读取、导出或清除浏览器 Cookie，也不会让官网会话自动退出。完整先导证据与未覆盖范围见 [`BROWSER_EXPORT_PILOT_2026-09-08.md`](BROWSER_EXPORT_PILOT_2026-09-08.md)。

开发验证中若只需确认官网详情响应是否提供作者字段，可先在官方书架页控制台执行 `window.FANQIELITE_AUTHOR_DIAGNOSTIC = true`，再执行完整导出脚本。此模式只请求书架和书籍详情，不请求阅读进度、不创建下载文件，也不显示字段值；弹窗只报告预先列出的作者候选字段分别出现了多少次 `string`、`null`、`array`、其他基础类型或缺失。刷新官方页面即可清除该临时布尔开关。该类型计数只能帮助定位字段结构，不能证明某个字段语义正确，也不是普通用户导出步骤。
