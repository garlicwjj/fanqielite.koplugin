# 一次性敏感 HTTPS 客户端审计

状态：**实验性扫码专用传输层已启用；合成门禁通过，PW3 测试账号验收未完成**。

## 当前结论

`ephemeral_http.lua` 为扫码子任务提供最小 HTTPS 请求边界。它复用 [`verified_tls.lua`](TLS_SECURITY_AUDIT.md) 的 KOReader CA 链与 SAN 主机名校验，并由 `qr_protocol.lua` 注入固定的初始化、轮询、书架、详情、可选进度和退出策略。只有用户主动确认实验入口后才会发起请求。

它只解决“受信任子进程怎样向预先审计的固定操作发送一次受限请求”。匿名运行时结构和合成协议已覆盖；它仍不证明真实账号授权主体、认证 Cookie 与退出撤销语义已经验收。

## 2026-08-31 公开前端路径审计

匿名读取官方 [`/bookshelf`](https://fanqienovel.com/bookshelf) 页面加载的公开脚本后，可以固定以下静态事实：

- Web 登录 SDK 配置包含 `aid=2503` 和 `appName=muye`。
- `qrcodeLogin.getQrcode({next})` 使用 GET 调用同源 `/passport/web/get_qrcode/`，并传递编码后的 `next`。
- `qrcodeLogin.checkQrconnect({token,next})` 使用 GET 调用同源 `/passport/web/check_qrconnect/`。
- SDK 应用退出路径为 `/passport/web/logout/`，官网包装层传入 `next=window.location.origin` 和 `need_redirect=0`。

审计过程没有调用上述任一端点，因此没有创建二维码、票据、Cookie 或账号会话。当时这些路径也没有写入 `ephemeral_http.lua` 的生产策略：端点名称不足以证明响应模式、Cookie 所有权或退出安全。2026-09-28 的匿名运行时复核和当前实验性接线见文末；本节保留为历史审计基线。

在无敏感内容的专用测试账号验证前，仍不知道：

1. 生成和轮询响应的字段名、类型、状态值、票据格式与有效期；
2. 二维码实际显示的 URL、用户必须使用的 App、授权页主体与确认文案；
3. `Set-Cookie` 的最小字段、`Domain`/`Path`/`SameSite`/有效期、同名覆盖和删除语义；
4. 轮询成功是否仅返回数据、设置当前连接的 Cookie，或要求额外请求；
5. 退出响应如何表示成功，以及是否真正撤销该次临时 Web 会话；
6. 完整流程在 KOReader 取消、超时和强制退出后是否留下可复用凭证或文件。

后续测试只能记录字段名、类型、固定状态和响应头名，不得记录值、完整 URL、二维码载荷、Cookie 或原始响应。当前实现仍遵守这条取证边界，并只允许支撑明确标为“实验性”的入口。

## 2026-09-07 专用测试账号的官网界面预检

用户明确批准电脑端官方授权、只读书架与退出验证，并确认 Chrome 当前登录的是无敏感内容的专用测试账号后，使用官方网页 UI 完成以下观察（未使用插件敏感 HTTP 客户端）：

- 桌面版 `/bookshelf` 显示两本书，均为未读；未打开正文、增删书籍或上传阅读进度。
- 账号菜单的“退出登录”执行后，页面显示“登录账号，同步在读书籍”和“登录番茄账号”，原书架不再显示。
- 从该登录按钮进入的页面包含“验证码登录”“扫码登录”；选择扫码后显示“打开番茄小说或番茄作家助手扫码登录”。
- 用户再次扫码后明确报告手机页面显示“登录番茄小说网”，并说明使用番茄小说 App 扫码。该登录目标文字来自用户现场反馈，不是根据官网扫码提示推断；尚无完整权限说明记录。

没有读取浏览器 Cookie、存储或原始网络响应，也没有保存二维码图像、载荷或账号标识。上述退出观察只证明当前浏览器 UI 回到未登录状态，不证明旧会话在服务器端失效，不证明 Cookie 清理、插件内存生命周期或浏览器导出脚本已经通过。当时尚无真实协议字段、轮询状态和退出撤销证据，因此客户端保持禁用；当前实验性实现不把这段历史观察当作真实退出验收。

用户随后报告已完成授权，Chrome 返回官方书架并显示相同两本未读书籍，但显示昵称与退出前不同，因此当时暂停后续账号读取。用户已确认仍为同一个专用测试账号；再次核对手机登录目标并确认登录后，浏览器也再次显示测试书架。账号身份疑问已由用户确认解除，不保存昵称，也不凭相同书架推断账号身份。随后浏览器脚本真实下载了两本未读书的最小 JSON，文件通过生产导入器格式验证；作者和已读进度没有出现在该样本中，分组、多页、大书架和失效登录也未覆盖。完整证据见 [`BROWSER_EXPORT_PILOT_2026-09-08.md`](BROWSER_EXPORT_PILOT_2026-09-08.md)。这些结果只证明官网浏览器登录及有限文件导出路径可用，不计作 Kindle 插件扫码导入、临时凭证清理或服务端退出验收。

此前内置浏览器访问书架被导航至带 `force_mobile=1` 的页面并显示下载 App 提示；改用已连接 Chrome 后可见桌面书架。仅记录环境差异，不据此推断官网书架已经移除或绕过移动端访问限制。

## 已实现的门禁

- 主机硬编码为 `fanqienovel.com`，调用方不能传入主机、URL、端口或代理。
- 构造客户端时必须提供代码内操作名到精确路径和 GET/POST 方法的白名单；路径不能包含查询串、片段、绝对 URL、双斜杠或 `..`。
- 调用时只接受 `body`、`cookie` 和 `headers` 三类参数；未知操作、动态 URL 参数和未列出的请求头在联网前拒绝。
- Cookie 请求头最大 16 KB，只在该次请求内存在；扫码流程使用受限内存 Cookie jar，不写文件、设置、缓存或后台刷新。
- POST 正文最大 64 KB；扫码子进程响应最大 2 MB，最终出管道结果仍受 256 KB 门禁约束；响应 `Content-Length` 不一致时拒绝。
- 禁止 LuaSocket 全局 HTTP 代理和所有重定向。
- 只有策略明确列出的响应头会返回子任务；其他账号相关响应头不暴露。
- 超时、证书、重定向、限流、服务异常和底层异常只返回固定中文分类，不拼接原始异常、状态文本、响应正文或凭证。
- KOReader 全局超时配置异常时不发起请求并尽力复位；请求后的复位异常会丢弃响应、隐藏异常对象并要求重启，不把未知全局状态误报为成功。
- 模块不导入 logger，不调用 `print()`、`io` 或 `os`，不写文件或进程输出。

策略在构造时会复制，之后修改调用方原表不会改变已授权路径。生产策略只存在于 `qr_protocol.lua` 的固定官方操作；合成测试使用 `/__synthetic__/...` 虚构路径，不连接网络。

## 敏感成功结果

请求成功后，正文和策略允许的 `Set-Cookie` 等响应头仍可能包含凭证或账号数据。它们只允许留在同一个可取消子进程中，用于完成下一次固定操作或转换成最小书架字段。调用方必须：

1. 不记录、不显示、不持久化原始成功结果；
2. 不把原始正文、Cookie 或响应表直接返回给 `ephemeral_task.lua`；
3. 在子进程内严格解析，再通过 `ephemeral_result.lua` 和 `ephemeral_import_task.lua` 的标准化与双重复验，只返回最小书架 JSON；
4. 完成或失败后删除所有可达凭证引用；
5. 接受 Lua 字符串无法原地可靠清零，以及 `SIGKILL` 时无法执行 Lua 清理的限制。

本模块自身不保存 Cookie；`ephemeral_cookiejar.lua` 在子进程内实现受限的多条 `Set-Cookie` 合并、同名覆盖和 `Max-Age=0` 删除。它不会持久化，也不把 Cookie 返回父进程。`Domain`、`Path`、`Secure` 和完整 `Expires` 语义没有被泛化成浏览器 Cookie 引擎，因为当前固定协议只向同一官方主机发出白名单请求；若官方行为变化，必须先用无敏感内容的测试账号重新审计，不能放宽后猜测。

## 合成证据

`tests/test_ephemeral_http.lua` 使用凭证 canary 覆盖：

- 策略为空、绝对 URL、查询串和路径穿越拒绝；
- 策略复制后不可由外部修改；
- CA/SAN 连接器复用、固定主机/路径/方法、POST 正文和允许凭证头；
- 未知操作、动态 URL、未列出头、CRLF 注入、GET 正文和代理在联网前拒绝；
- 原始异常、证书失败、超限响应和重定向不回显 canary；
- 未列出的响应头不暴露；
- 正常与 HTTP 异常请求都会调用 KOReader 网络超时复位；配置函数异常时不联网并尽力复位，复位函数自身异常时固定停止、丢弃响应且不回显 canary。

这些测试不发真实请求，也不能证明真实成功响应不会在未来的端点任务代码中被误传到日志或匿名管道。

## 2026-09-28 协议接线与匿名运行时证据

当前官方脚本和匿名请求确认二维码初始化、轮询仍为 GET，应用参数为 `aid=2503`、`appName=muye`；初始化返回约 60 秒有效期、官方 `reading.snssdk.com` 扫码 URL、票据和三种预授权 Cookie，未扫码轮询返回 `status=new`。审计没有扫码、登录或输出任何值。

`ephemeral_http.lua` 现支持代码声明的查询字段白名单、确定性百分号编码、多值 `Set-Cookie` 受限返回和 2 MB 子进程响应上限；`ephemeral_cookiejar.lua` 实现内存合并、同名覆盖、`Max-Age=0` 删除、数量/名称/值/总长限制。`qr_protocol.lua` 固定官方端点和字段映射，`qr_import_task.lua` 在扫码确认后的同一子进程内完成轮询、书架读取、退出和最小结果编码。原始正文和认证 Cookie不会返回 UI。

## 继续 No-Go

- 当前硬编码主机不能覆盖未经审计的其他官方域名，禁止为了“先跑通”而放宽为后缀或任意 HTTPS；
- 真实成功后的 Cookie 集合、用户看到的授权主体、二次验证和退出撤销语义尚未用专用测试账号确认；
- 未扫描真实 KOReader 日志、崩溃输出、设置、缓存和用户分区文件变化；
- 未在 PW3 验证扫码可读性、取消、过期、网络切换、系统时间错误和强制退出。

因此该模块只允许支撑明确标为“实验性”的入口；上述证据完成前不得作为稳定版能力、不得用于主要账号首次验证，也不得放宽凭证落盘边界。
