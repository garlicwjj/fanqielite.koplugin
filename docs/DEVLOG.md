# 从零到一

## 起点

这个项目源于一个很直接的问题：已经能在 Kindle Paperwhite 3 上运行 KOReader，能否也用它阅读番茄小说？

第一步不是编写界面，而是确认技术边界。调研发现，番茄小说的官方阅读网页包含服务端渲染的章节状态；目录也可以由官方网页接口取得。但此前看到的非官方实现会依赖第三方聚合正文源，这不符合本项目希望保持的范围。

因此，0.1.0 确立了几条原则：

- 只请求 `fanqienovel.com` 官方网页。
- 不登录，不接触账号 Cookie 或个人书架。
- 不批量下载整本书。
- 不绕过付费、登录或章节锁定。
- 无法可靠解析时明确失败，不把乱码写入缓存。

## 第一个原型

原型验证了三件关键事情：

1. 书籍页面可以提取书名和书籍 ID。
2. 官方目录响应可以整理成 KOReader 可操作的章节列表。
3. 公开章节中的 PUA 字符可按当前映射还原成正常文字。

插件采用很小的分层：`http.lua` 负责受限的网络请求，`parser.lua` 负责页面和章节解析，`pua.lua` 负责字符映射，`storage.lua` 只管理插件自己的缓存，`main.lua` 连接 KOReader 菜单和阅读器。

## 第一次完整自检

在准备 0.1.0 时，自检发现并修复了三个会影响真实使用的问题：

- 中文长度最初按 UTF-8 字节数统计，可能误判短预览；现改为按 Unicode 字符计数。
- 目录定位最初调用了 KOReader 中不存在的方法；现使用 2026.03 实际提供的分页接口。
- 网络底层抛出异常时可能无法恢复全局超时；现保证请求结束后复位。

最终验证覆盖 Lua 5.1 语法、核心离线测试、官方书籍页、目录、公开章节和登录墙页面。桌面端验证通过后生成了第一个安装包。

## 第一次 Kindle 实机验证

2026-08-16，0.1.0 被复制到 Kindle Paperwhite 3（固件 5.16.2.1.1）上的 KOReader 2026.03。KOReader 正常启动，工具菜单出现“番茄小说（实验版）”，离线说明页面可以打开。连接 Wi-Fi 后，测试书籍的书名与当时最新的 88 章目录正常显示；打开第一章后，正文完整、无乱码，KOReader 翻页正常。

这次结果把项目状态从“桌面端可行性验证”推进到了“单台 PW3 实机验证通过”。它仍不是对所有 Kindle 型号、KOReader 版本或未来网页结构的兼容性保证。

## 多书本地书架

稳定版候选的第一项改造从本地数据开始，而不是先做账号登录。原因是登录属于可选能力，不能成为日常阅读体验的前提。

新书架以带版本号的数据结构保存多本书，每本书独立记录目录、最后阅读章节、添加时间、目录更新时间和最近打开时间。首次启动新版时，0.1.0 的单书设置会自动迁移；同时保留并同步旧字段，使用户仍可降级回 0.1.0。刷新目录时优先按章节 ID 找回原阅读章节，避免目录前方新增章节后进度错位。

删除边界被刻意拆成两个动作：“从书架移除”不删除缓存，“清理缓存”不删除书籍和进度，且都需要用户确认。缓存清理只接受数字书籍 ID，并只删除插件目录内符合数字章节名规则的 XHTML 与临时文件。

## 网络边界审计

审计发现原型虽然设置了 20 秒总超时，但自定义响应接收器没有实际检查总耗时；慢速分块响应可能持续阻塞界面。修复后，接收器同时检查累计时间和 1 MB 大小限制，并保证请求成功、失败或底层异常时都恢复 KOReader 的全局网络超时。

网络模块现在只接受 `https://fanqienovel.com/` 地址，明确禁用重定向，并检查声明的响应长度。超时、证书、重定向、权限、限流、页面不存在和服务端错误会转换成可操作的中文提示，同时说明本地数据没有改变。

## 安全 JSON 导入

浏览器文件导入先实现 Kindle 端的严格接收边界。插件只显示并接受名为 `fanqielite-bookshelf.json` 的文件，读取前限制为 256 KB，解析后要求固定格式版本、连续书籍数组、最多 500 本、字符串 ID、字段长度和 0 到 1 的阅读位置。

导入采用字段白名单，并递归拒绝 Cookie、Token、session、CSRF、密码、手机号和授权头等凭证字段。全部书籍通过验证后才显示新增与更新数量；用户再次确认后才写入本地书架。导入已有书籍时保留其目录、缓存和本地阅读进度；新书首次打开时再从番茄官方地址获取目录。

## 搜索功能的失败实验

2026-08-16 检查了番茄官网当前使用的 `/api/author/search/search_book/v1`。未登录的直接只读请求返回 HTTP 200 但正文为空；在官方搜索页执行相同关键词时，页面出现滑块验证，结果保持为空。

这意味着“在 Kindle 中直接按书名搜索”目前没有经过验证的稳定官方路径。项目不会绕过验证码，也不会为了填补入口而接入第三方搜索源。界面应继续诚实说明当前只支持官方链接或 ID；搜索只有在找到合法、稳定且可在 Kindle 上完成的官方流程后再实现。

## 缓存完整性边界

章节缓存不能只凭文件存在就交给 KOReader 打开。插件现在会先检查大小、固定 XHTML 结构、完整结尾和 XML 非法控制字符；损坏缓存会被拒绝，并在不改变书架与阅读进度的前提下尝试联网重新获取。

写入仍采用同目录临时文件和原子改名，同时开始检查 `write` 与 `close` 两个阶段。磁盘写满、只读或关闭文件失败时会删除未完成的临时文件，保留原有正式缓存，并提示用户检查空间或只读状态。

## 设置写入完整性

核对 [KOReader 2026.03 的 `LuaSettings`](https://github.com/koreader/koreader/blob/v2026.03/frontend/luasettings.lua) 与 [`util.writeToFile()`](https://github.com/koreader/koreader/blob/v2026.03/frontend/util.lua#L1141) 后确认，`LuaSettings:flush()` 不会把底层写入失败返回给调用方，而底层也未检查 `write()` 和 `close()` 的结果。插件不能用 `flush()` 的返回值证明书架或进度已经落盘。

因此插件设置改为先生成临时 Lua 设置文件，调用 KOReader 的 `fsyncOpenedFile()`、关闭并重读校验后，再原子替换正式文件；每次替换前用同样流程保存上一版 `.old`。写入、同步、关闭、重读校验或改名任一步失败时，本次内存修改会回滚，界面会说明设置未保存及检查空间/只读状态。网络操作的用户提示也不再展示 Lua 调用栈。

## 真正可取消的网络任务

KOReader 2026.03 官方的 [`Trapper:dismissableRunInSubprocess()`](https://github.com/koreader/koreader/blob/v2026.03/frontend/ui/trapper.lua) 会让 UI 保持响应，并在用户点按取消时终止和回收子进程。插件只把无副作用的官方 HTTP GET 放进子进程；解析、书架修改、缓存写入和设置保存仍留在主进程，并且只在完整响应返回后发生。

因此取消书籍信息、目录或章节请求时，不会留下临时下载、半份响应或内存里的书架修改。并发点击会被“已有网络操作”门禁拒绝。该机制仍需在 PW3 上验证点按响应、强制退出和 Wi-Fi 切换。

## 解析安全变体

章节与书籍 ID 现在统一要求至少 10 位数字，并拒绝响应 ID 与请求不一致。锁定判断同时覆盖布尔 `true`、数字 `1` 和字符串 `"1"`/`"true"`，避免接口序列化方式变化后把受限章节误当成公开正文。

PUA 解码前的 UTF-8 扫描补齐了续字节、过长编码、代理区和超过 U+10FFFF 的边界。无效 UTF-8 与未知 PUA 都会在生成缓存前安全拒绝；合法四字节字符保持不变。自动测试同时覆盖畸形目录、书籍/章节 ID 不一致、数字和字符串锁定标志。

## 缓存清理的部分失败

清理缓存过去只统计删除成功的文件，删除失败会被静默忽略，界面仍可能显示“已清理”。现在目录打开/遍历错误会直接失败；若只删除了部分文件，插件会分别报告成功数、失败数和首个系统错误，并明确未删除缓存仍可使用、书架和进度没有改变。

删除白名单仍只允许数字章节名的 `.xhtml` 与 `.xhtml.tmp`。目录里即使出现未知文件也不会删除；因此未知文件导致空目录移除失败时不会把它当成缓存清理失败。

## 本地书架安全导出与数据设置

插件现在可把本地书架导出为与严格导入器相同的版本 1 JSON。生成内容只使用书籍白名单字段，并在写入前通过导入验证；同目录临时文件完成写入和同步后会再次解析验证，随后原子替换固定文件名并做最终复验。失败不会改动书架、缓存或插件设置，也不会把部分写入报告成成功。

导出当前章节时只使用插件确实记录的章节 ID 与标题，不虚构章节内百分比；从已验证文件导入且尚未加载本地目录的合法百分比可以原样迁移。“设置与数据”同时集中显示导入/导出、缓存与隐私边界，以及仅供用户手动执行的完整卸载路径，插件本身不执行自动删除。

## 官方浏览器验证挑战

2026-08-17 对番茄官网当前公开搜索流程的只读审计确认：网页使用 `/api/author/search/search_book/v1`，但匿名直连可能返回 HTTP 200、空正文和 `Bdturing-Verify` 滑块验证响应头。使用插件现有浏览器 User-Agent 仍会触发；搜索页本身也不服务端输出结果。Kindle 无法可靠完成该网页滑块，因此插件不会尝试绕过或复用验证令牌，书名搜索暂不能据此宣称稳定可用。

网络层现在会识别官方验证响应头而不记录或展示其值，明确提示“官方安全验证、Kindle 无法显示、稍后重试或粘贴官网链接”；其他无挑战头的空响应也会安全拒绝。两种情况都不会进入解析、缓存或书架写入阶段。

在此边界上，书名/作者搜索采用有限的“尽力而为”模式：只访问上述番茄官方 HTTPS 接口，只请求第一页 10 条结果，并严格验证连续数组、数量、字符串书籍 ID、标题和作者字段。无效条目不会进入书架；选中结果后仍复用既有书籍页与目录验证流程。官网正常返回时新手可直接搜索加入，出现滑块挑战时则明确回退到粘贴官网链接，不能把该能力描述成所有网络下都可用。

## KOReader 数据目录实机核对

2026-08-17 在上述 PW3 的用户盘核对确认，`DataStorage:getDataDir()` 对应 `koreader/`，现有章节缓存与 KOReader 的相邻 `.sdr` 阅读位置数据均位于 `koreader/fanqielite/`。运行时代码原本已通过 `DataStorage:getDataDir() .. "/fanqielite"` 使用正确位置；本次仅修正文档与卸载界面的错误路径提示，不迁移或删除任何数据。
