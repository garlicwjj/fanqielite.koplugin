# 一次性扫码导入威胁模型

状态：**实验性端到端实现与合成门禁；尚未完成 PW3 测试账号真实扫码和远端退出验收**。

本文定义“一次性扫码导入官方书架”的安全边界、生命周期、失败行为和验证证据，并记录当前实验实现。它不提供共享凭证或绕过方法；代码可用不等于真实账号安全验收完成。

## 安全目标

1. 本地书架始终是默认且完整的使用方式；拒绝扫码不能影响添加、阅读、缓存和 JSON 导入导出。
2. 扫码必须由用户主动发起，并显示：“本次扫码只用于导入书架，插件不会保存账号登录。”
3. 只读取书架导入所需的书籍 ID、书名、作者、封面、最近章节和阅读位置，不读取或上传其他账号数据。
4. Cookie、sessionid、CSRF、Token、授权头、二维码载荷和退出票据只允许短暂存在于内存引用中。
5. 成功、失败、取消、超时、二维码过期、退出失败和强制退出都不得把凭证写入设置、缓存、日志、错误提示、崩溃输出或导出文件。
6. 在用户确认前不得修改本地书架；任何终止路径都保留原书架、进度和缓存。
7. 获取最小书架数据后尽快调用番茄官方退出接口；本地安全不能依赖退出请求成功。

## 非目标与禁止事项

- 不实现长期登录、后台同步、自动刷新官方书架或上传阅读进度。
- 不要求用户复制浏览器 Cookie，不共享 Cookie、公共 Token 或第三方代理账号。
- 不读取番茄 App 私有数据，不绕过扫码确认、验证码、登录墙、付费或章节锁定。
- 不把凭证与“加密密钥”一起保存在 Kindle；USB 可读取的同一用户分区不是可靠密钥库。
- 不把官方响应、请求头、二维码原图或完整个人书架转储到文件中调试。

## 需要保护的数据

| 数据 | 分类 | 允许存在的位置 | 最终处理 |
| --- | --- | --- | --- |
| QR 载荷、轮询票据、设备码 | 瞬时凭证 | 当前扫码流程的内存对象和屏幕 | 到期或离开流程立即清除引用 |
| Cookie、sessionid、CSRF、Token、授权头 | 高敏感凭证 | 经审计的官方 HTTPS 传输内存 | 退出尝试后立即清除引用，绝不落盘 |
| 官方退出票据或会话标识 | 高敏感凭证 | 退出请求内存 | 请求结束后立即清除引用 |
| 账号 ID、手机号、头像、用户名 | 非导入所需私有数据 | 最多只在未解析响应内短暂出现 | 不复制到标准化结果，随后清除 |
| 书籍 ID、书名、作者、封面 | 最小书架数据 | 标准化待确认列表、本地书架 | 用户确认后可持久化 |
| 最近章节与阅读位置 | 私有阅读数据 | 标准化待确认列表、本地书架 | 用户确认后可持久化，不上传 |

Lua 字符串不可原地覆写，垃圾回收也不等于密码学意义的内存清零。因此“清除”只能表示移除所有插件可达引用并尽快结束持有它们的子任务。强制退出后由操作系统回收进程内存；威胁模型不能声称字节已被可靠擦除。

## 信任边界

1. **用户与屏幕**：二维码可能被旁观、拍照或重放，必须短时有效并清楚显示到期状态。
2. **KOReader 主进程**：持有 UI、本地书架和设置；持久化只允许显式白名单状态。
3. **可取消网络子进程**：固定源码审计确认 KOReader `Trapper` 返回值使用匿名管道，但默认复杂序列化和未捕获异常存在日志风险，取消还会以 `SIGKILL` 跳过清理。凭证只允许经过独立简单字符串门禁；详见 [`SUBPROCESS_SECURITY_AUDIT.md`](SUBPROCESS_SECURITY_AUDIT.md)。
4. **Kindle 用户分区**：设置、缓存、日志和导出文件可通过 USB 读取，按不可信持久介质处理。
5. **番茄官方 HTTPS 服务**：只允许经测试账号重新确认的精确官方域名和路径，响应全部视为不可信输入。
6. **手机端官方确认**：用户必须在番茄官方界面明确确认；插件不能模拟确认或降低官方验证强度。

## 目标生命周期

| 状态 | 可持有敏感数据 | 允许的下一步 | 离开时必须做什么 |
| --- | --- | --- | --- |
| `idle` | 无 | 用户主动开始 | 显示隐私说明 |
| `initializing` | 临时请求关联值 | 得到官方 QR 或失败 | 失败时清除全部引用 |
| `qr_pending` | QR 载荷、轮询票据 | 已确认、过期、取消、超时 | 关闭 QR，停止轮询，清除载荷 |
| `authorized` | 临时会话凭证 | 读取一次最小书架 | 禁止设置写入和日志输出 |
| `fetching` | 会话凭证、未信任响应 | 严格验证或失败 | 丢弃原始响应；不改变书架 |
| `logging_out` | 仅退出所需凭证 | 退出成功或失败 | 无条件清除全部凭证引用 |
| `ready_to_confirm` | 仅标准化最小书架数据 | 用户确认或取消 | 不再持有可复用凭证 |
| `committing` | 标准化书架数据 | 原子保存或回退 | 保存失败恢复上一版设置 |
| `done` | 无凭证 | 返回本地书架 | 明确报告导入结果和退出状态 |

目标设计在显示最终导入确认框前完成退出尝试并清除凭证。这样用户停留在确认框、取消导入或设备随后休眠时，都不需要继续持有官方会话。

当前 `ephemeral_session.lua` 管理单实例运行代号、五分钟总时限、二维码过期、取消、迟到结果隔离、远端清理后的最小书架确认和提交失败重试。父进程只在 `qr_pending` 阶段持有二维码与包含匿名预授权 Cookie 的受限轮询票据；扫码确认后的认证 Cookie、书架响应和退出请求全部留在 `qr_import_task.lua` 的子进程中。成功时父进程只收到经 `ephemeral_result.lua` 双重验证的标准化书籍；失败时只收到固定分类。Lua 字符串不能可靠清零，强制杀死 KOReader 时也不能保证执行清理代码，因此仍需要真机与测试账号证据。

### KOReader 2026.03 内存二维码源码审计

目标版本 `v2026.03` 固定到 KOReader 提交 [`825b9bc`](https://github.com/koreader/koreader/commit/825b9bced0eb666b45af4208e1c0095b88d38b0d)，其 `koreader-base` 子模块为 [`7a46ea3`](https://github.com/koreader/koreader-base/tree/7a46ea3812539083ee25b06f0c81ac58b1356ee0)。官方 [`QRMessage`](https://github.com/koreader/koreader/blob/v2026.03/frontend/ui/widget/qrmessage.lua) 把文本交给 [`QRWidget`](https://github.com/koreader/koreader/blob/v2026.03/frontend/ui/widget/qrwidget.lua)；后者调用纯 Lua [`ffi/qrencode.lua`](https://github.com/koreader/koreader-base/blob/7a46ea3812539083ee25b06f0c81ac58b1356ee0/ffi/qrencode.lua) 生成矩阵，再直接创建 `BlitBuffer` 交给 `ImageWidget.image`。按这些源码推断，该路径不需要二维码图片文件；`ImageWidget` 对已有 `image` 走内存加载，并在释放时回收可处置的 `BlitBuffer`。

审计同时发现 `QRWidget` 会静默截断超过 2953 字节的文本，授权二维码不能接受这种行为。`qrdisplay.lua` 因此在构造控件前拒绝空值、控制字符、超过 2048 字节的载荷和超过五分钟的显示时间；关闭成功后删除文本和回调引用，关闭异常则保留可重试句柄并明确报告未关闭。该结论目前只证明源码路径与合成适配行为，不证明 PW3 上二维码一定可扫码、不产生其他 KOReader 运行痕迹，或强制退出时 `free()` 必然执行。

## 网络与响应要求

- 只访问现场审计确认的番茄官方 HTTPS 域名；域名、路径、方法和用途逐项白名单。
- 禁止跟随重定向，禁止第三方图片、统计、代理或聚合服务参与授权。
- 每个请求限制响应大小、单次超时和整个扫码流程总时限；轮询有固定最小间隔和最大次数。
- 协议需要的敏感头不得进入通用错误字符串；UI 只显示固定分类错误。
- 禁止记录请求/响应头、`Set-Cookie`、完整 URL 查询串、二维码载荷或响应正文。
- 所有 ID、数组、字段、长度、HTTPS 封面和阅读位置在进入本地书架前执行严格白名单验证。
- 服务端出现验证码、品牌/授权主体不一致或未知确认页面时立即停止，不尝试绕过。

当前 `fanqielite.http` 与 `networktask` 继续只处理无凭证公开 GET。扫码使用独立的 `ephemeral_http.lua`：复用同一 TLS 门禁，把主机固定为 `fanqienovel.com`，并对白名单操作、路径、方法、查询字段、请求头、响应头和大小逐项限制。`ephemeral_cookiejar.lua` 只在内存解析、合并和删除受限 Cookie；不创建 Cookie jar 文件。`qr_protocol.lua` 固定当前官方初始化、轮询、书架、详情、可选进度和退出流程；二次验证或未知状态安全停止。`qr_import_task.lua` 只允许经过现有 JSON 白名单、标准化编码和父子两侧复验后的最小书架越过匿名管道。真实响应解析器的普通标题字段仍需成功产物审计，不能仅凭字段名证明其中绝无秘密。

## 持久化与日志门禁

- `main.lua:state_table()`只投影本地书架、活动书籍、兼容字段和导入目录；瞬时会话属于插件运行对象，不能加入该表。
- `Persistence.write()`在创建主文件或 `.old` 备份前递归拒绝账号、二维码、票据、会话、Cookie、CSRF、Token 和授权头字段。
- 扫码结果必须先转换成与 `Library.import_books()`兼容的最小书籍记录；额外字段不会进入本地书籍对象。
- JSON 导出继续使用字段白名单，不得新增账号 ID、登录状态或同步时间字段。
- 日志只允许固定阶段标记，例如“二维码已显示”“已取消”“最小数据验证失败”；禁止拼接异常对象、URL、路径、响应或头值。
- 错误提示必须说明发生了什么、现有数据是否改变和下一步操作，但不得回显服务端原文。

字段名门禁只能阻止显式凭证字段，不能证明某个普通字段值中没有被误塞入秘密。因此仍需使用合成凭证 canary 覆盖状态投影、导入、导出、日志和错误路径，并在测试账号实测后检查真实产物。

## 主要威胁与控制

| 威胁 | 可能后果 | 必须控制 |
| --- | --- | --- |
| QR 被拍照或重放 | 他人尝试接管临时授权 | 官方短时效、单次使用、明确过期、取消后停止轮询 |
| 授权主体或品牌异常 | 用户确认给错误应用 | 显示官方主体；与预期不一致立即停止并重新审计 |
| 重定向或域名替换 | 凭证发送到第三方 | 精确域名/路径白名单，任何重定向失败关闭 |
| 恶意或变化的书架响应 | 写入超大、畸形或凭证数据 | 大小限制、字段白名单、全量验证后再确认 |
| 错误或日志拼接原始对象 | 凭证进入日志/屏幕 | 固定错误分类和固定阶段日志，不返回原始头/响应 |
| JSON 解析器异常包含输入片段 | 畸形响应或误选文件的秘密出现在 UI/日志 | 解码层不字符串化异常对象或错误正文，只返回固定分类 |
| 调用方修改、扩展或保留凭证表 | 会话持有未知字段、退出使用被替换的 Cookie 或回调后表仍可读 | 授权入口复制固定字段并限制大小/控制字符；拒绝独立 sessionid 与未知键；回调返回后清空共享表 |
| 设置备份复制瞬时会话 | 主设置和 `.old` 同时泄露 | 候选状态与上一版状态都通过凭证字段硬门禁 |
| 取消、超时或二维码过期 | 轮询继续、会话残留 | 单一终止函数，幂等停止任务、退出尝试和清除引用 |
| 强制退出或进程崩溃 | 无法调用官方退出 | 绝不落盘；要求会话短时失效，并用测试账号验证远端状态 |
| 官方退出失败 | 远端会话可能仍有效 | 本地无条件清除；明确告知用户，安全不依赖退出成功 |
| 重复点击开始/确认 | 并行会话或重复导入 | 单实例状态机、忙碌门禁、提交操作幂等 |
| QR 图片写入临时文件 | USB 可恢复凭证图像 | 使用已审计的 KOReader `QRMessage` 内存路径；真机检查文件变化和关闭回收，异常时暂停接入 |

## 自动测试要求

使用完全虚构的会话和固定传输夹具，至少覆盖：

1. 成功、初始化失败、扫码取消、二维码过期、轮询超时、服务错误和畸形响应。
2. 用户确认前书架不变；取消和所有失败路径设置、缓存与导出不变。
3. 会话清理可重复调用，成功、失败和取消后敏感字段均不可达。
4. 退出成功、退出超时和退出失败都执行本地清理；失败提示不含 canary。
5. 重复点击只创建一个会话；旧轮询结果不能写入新会话。
6. `state_table()`、设置主文件、`.old`、缓存、导出、固定日志和错误文本均不包含 canary。
7. 敏感字段即使误入候选设置，也在任何文件创建前被拒绝。
8. 强制终止模拟不产生临时二维码、Cookie jar、响应转储或调试文件。

## 测试账号与真机验证

只有上述合成测试通过后，才可使用无手机号展示、无敏感书籍的专用测试账号：

1. 重新确认当前官方域名、授权主体、二维码文案、Cookie 名称与有效期、轮询状态和退出接口。
2. 只导入少量测试书，不上传进度，不修改官方书架。
3. 分别验证成功、取消、过期、超时、退出失败和 KOReader 强制退出。
4. 测试前后检查插件设置、`.old`、缓存、导出、KOReader 日志和崩溃输出；报告只记录文件哈希、字段集合和是否命中，不记录凭证值。
5. 在官方账号安全页面或等价官方机制确认退出是否使临时 Web 会话失效。
6. 完成后撤销测试会话并更换测试账号凭证。

不得使用项目所有者的主要账号做首次验证。

匿名重新读取官网当前书架页后，固定了新的公开资源：`BookShelf.aa3c8ca8.js`（SHA-256 `d94f4b0794a9c755aba48ba2b550178af9a90029fe95884925c5d88e9ef4d7d8`）与 `muye_5f7ec5dd.js`（SHA-256 `4f860a44b20b709a1ecb3a138fb7d996874ae4540d3522d95e721fc0c53d7a8e`）。公共包仍使用 `aid=2503`、`appName=muye`、`region=cn`，并公开 `/passport/web/get_qrcode/`、`/passport/web/check_qrconnect/`、`/passport/web/logout/`。

本次还只匿名调用二维码初始化和一次未扫码轮询，没有扫码、登录或使用账号。脱敏结果证明：初始化 HTTP 200、`message=success`、`error_code=0`；二维码约 60 秒有效；真正应编码的是 `https://reading.snssdk.com/ucenter_web/app/sdk-next` 的约 480 字节 URL，而不是 3424 字节的二维码图片字符串；初始化设置 `passport_csrf_token`、`passport_csrf_token_default`、`reg-store-region`，未扫码轮询返回 `status=new`。输出只记录字段名、类型、长度、Cookie 名称和固定状态，没有记录票据或 Cookie 值。

运行时代码据此固定查询字段、二维码主机/路径/票据绑定和 `new/scanned/confirmed/expired/refused` 安全状态集合。未识别状态、`error_code=2046` 二次验证、重定向或响应结构变化都会停止。该证据仍没有证明确认成功后的 Cookie 集合、书架授权、官方主体、退出撤销或强制退出后的远端状态。

以下事实没有用专用测试账号和 PW3 验证前，实验入口不得升级为稳定能力：

- 用户手机看到的授权主体、确认页面和成功/拒绝/二次验证状态仍未验证。
- QR 的短时效和票据绑定已由匿名初始化及本地验证器覆盖，但单次使用与取消后的远端状态仍未验证。
- Cookie/CSRF 的最小集合、有效期和官方退出/撤销接口的真实语义。
- KOReader `QRMessage` 内存路径在目标 PW3 上的扫码可读性、关闭回收和前后文件变化证据。
- 真实扫码 HTTP/Cookie 子任务是否会写 Cookie jar、临时文件、请求日志、stdout/stderr 或崩溃残留。
- 强制退出后远端会话的自然失效时间和可验证撤销路径。

2026-08-16 的早期只读观察曾出现与预期产品名称不一致的授权提示；该观察可能已经过时，只能作为重新核对授权主体的风险提示，不能作为当前接口证据。

只要官方要求绕过验证、必须长期保存会话、必须把二维码或 Cookie 写入用户分区，结论就是立即关闭实验性扫码，继续提供完整本地书架和无凭证 JSON 导入。真机证据不足时保持“实验性”，不得宣传为稳定能力。

## 发布门禁

威胁模型、合成测试和持久化门禁只允许进入原型阶段。真实测试账号验证、凭证产物审计、强制退出验证和项目所有者明确确认全部完成前，扫码入口必须保持“实验性/开发中”，不得作为稳定版能力宣传。
